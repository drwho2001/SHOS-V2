Encounters form + positive-result red state — four fixes

Dark mode, 393dp. Each section shows what ships today and what the fix looks like. Nothing here is built into the app yet — this is the review pass.

1Add/Edit Encounter — tabs pin too low

The tab strip is sticky at STICKY_SUBHEADING_TOP = calc(env(safe-area-inset-top) + 58px). That token assumes the screen banner includes the safe-area inset (it does on My Profile). The encounter sheet instead spends the inset on the sheet's own paddingTop, and its pink banner is a 58px bar stuck at top: 0. So the tabs pin one inset lower than the banner's real bottom — on a 24dp Android status bar that is a 24px band of page background above the tabs.

Fix. Measure the sheet banner with a ref and pass that px value to FormTabs as stickyTop — var(--shos-sheet-banner-h, 58px). Never stored. The chip is computed at render (protectionUsed contains no barrier entry). Writing a synthetic “No barrier method” record would be a lie the moment the user adds a condom, and would break the registry's id references. It appears in three places: the picker, the read row, and the encounter card's protection chip group. Name matching is case-insensitive and trimmed, because the registry is user-editable.

3Kinks / chems — order by how often you use them

The picker's sort looks “recent” up against value — the form's current selection — but selected entries are filtered out of the suggestion list before sorting. The comparison can therefore never be true and the list falls straight through to a.name.localeCompare(b.name). That is why it reads A–Z no matter how many encounters you have logged.

4Positive test = the red state, clinic or home

Testing already colours a row red whenever a recorded result is positive, and the setting never enters that test — a home sample and a clinic sample are the same red. Clinic visits are the gap: their detail screen shows a linked positive result in red text, but the list row has no red state at all, so a visit with a positive result looks identical to a contraceptive review.

The rule, stated once. Red means a positive result is recorded on this record — never “the test was done at the clinic”. A clinic visit inherits the state from its linked tests (linkedTestIds); it does not store a result of its own, so there is exactly one source of truth and no way for the two screens to disagree. The older visit keeps its red border under the fade, because age does not make a positive result untrue; the fade and the “Older visit” pill still carry the age signal.
