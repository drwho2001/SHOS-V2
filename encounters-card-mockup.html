Real data fields used

From encounter schema (encounterRepository.js):
• title · date (single datetime) · dateEnd (optional) · isDateTime
• attendeeIds · locationId · encounterType · enjoymentRating · notes
• myPosition (user's perspective: "Anal - giving", "Oral - receiving") — teal
• myRole · protectionUsed (registry: Condom/PrEP/PEP/None) — green
• kinksInvolved — purple
• whereICame · whereHeCame (registry: Internal/External cum location) — pink
• loadsCount · fistCount · chemsAlcoholUsed · myDoxyPepStatus · myPrepCoverage
• locationName resolved via LocationsRepository.getById(encounter.locationId)

Derived (not stored):
• Climax — derived from whereICame/whereHeCame having any value other than "Didn't happen". Shown as subtle droplet only when data exists.
• End time — dateEnd field if set, shown after start time

NOT stored per encounter (removed):
• Body sites as separate chips — covered by myPosition
• Separate climax field — derived only
• Medication chips as standalone — PrEP coverage shown under medication chip with safety caveat

Chip colours use CSS variables from designTokens.js ACCENTS:
• Position (me) — teal var(--home-teal) = #008585
• Activities/kinks — purple var(--encounters-purple) = #7F30A6
• Protection/contraception — green var(--protection-green) = #5fd9a4
• Medication — healthcare blue var(--healthcare-blue) = #5b9bd5
• Cum/loads — pink var(--cum-pink) = #E24E9C

Colour override note: If user changes module colours via Design screen, CSS variables update and all chips/tints follow automatically. No hardcoded hexes in chip styling.

LoadsCount ambiguity: loadsCount is a single aggregate number per encounter. whereICame/whereHeCame can have multiple values. The card shows loads as an unlinked number — it does NOT map to a specific cum location. At session level, loads tally across encounters is more meaningful.
